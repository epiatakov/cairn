# Evals

cairn claims that a shared brain makes coding agents better. That claim needs numbers, and
the numbers need a method someone else can rerun. This page describes the two harnesses in
`evals/`, what they measure, and where they can mislead.

| Harness | Question | Cost | Runs in CI |
| --- | --- | --- | --- |
| Retrieval eval (`evals/retrieval/`) | Does `cairn search` put the right entry at the top? | Free, offline, deterministic | Yes, with a regression gate |
| Agent A/B (`evals/agent/`) | Does an agent with brain recall finish more tasks and repeat fewer known failures? | API credits per run | Mock runner only |

Both use the eval brain in `evals/brain/`, not `examples/brain/`, so the examples in the
README can change without moving the numbers.

## Eval brain

42 entries (15 facts, 17 issues, 6 skills, 4 notes), all generic, publicly known developer
pitfalls and procedures. It is built to be harder than a set of unrelated notes:

- **Distractors that share vocabulary.** CRLF in shell scripts sits next to a UTF-8 BOM
  breaking the shebang and Python's `csv` writing blank rows on Windows. Two Docker caching
  entries, two SQLite entries, lockfile facts next to the npm lockfile issue.
- **A stale near-duplicate** (`npm-ci-out-of-sync-lockfile`) with weaker advice than the
  active entry. Both count as relevant: stale entries stay searchable by design.
- **An archived entry** (`rg-glob-broken-on-windows`). Every retriever must skip it.
- **Cross-links.** Several bodies contain `[[id]]` links, which turned out to matter (below).

## Part A: retrieval eval

### Dataset

`evals/retrieval/queries.json` holds 50 labeled queries. Each lists the entry ids that answer
it; a hit on any of them counts.

| Kind | Count | Example |
| --- | ---: | --- |
| exact | 8 | `SQLite WAL mode concurrency` |
| paraphrase | 12 | `config file turns the country code for Norway into false` |
| error | 10 | `/usr/bin/env: 'bash\r': No such file or directory` |
| vague | 10 | `timezone bug` |
| none | 10 | `terraform state lock could not be acquired` (no right answer) |

The no-answer queries are in-domain on purpose, and several share words with real entries
(`lock`, `checksum mismatch`, `indent with spaces`, `windows ... builds`).

The queries and labels were committed before any scoring code existed (see the git history
of `evals/retrieval/queries.json`) and have not been edited after seeing results.

### Retrievers

All three see the same live (non-archived) entries, return at most 10 results, and break
ties by id.

- **`cairn-bm25f`**: cairn's own search through the public `Brain.search` API. BM25F with
  title, tags and body weighted 3 : 2 : 1 (see [design.md](design.md)). `[[link]]` ids in
  bodies are not indexed (see "Changes after the first run").
- **`bm25-flat`**: the same BM25 (same tokenizer, `k1`, `b`, and the same link handling), but
  over a single field with title, tags and body concatenated. The only difference from cairn
  is field weighting.
- **`substring`**: grep-style. The score is the share of distinct query words found as
  substrings of the lowercased entry text. It drops cairn's stopwords, otherwise `the` would
  match everything, but has no stemming, no IDF and no field weights.

### Metrics

On the 40 answerable queries:

- **hit@1, hit@3**: share of queries with a relevant entry at rank 1, or in the top 3.
- **MRR**: mean of `1 / rank` of the first relevant entry (0 if not in the top 10).

On the 10 no-answer queries:

- **any result**: share that return anything at all. This is what `cairn search` does today.
- **FP at threshold**: share whose top score clears a per-retriever threshold. Raw scores are
  not comparable across retrievers, so each gets its own operating point: the lowest score
  that still keeps 90% of its correct top-1 hits on answerable queries. The no-answer queries
  never influence the threshold.
- **recall gate** (cairn only): `cairn.recall.recall`, the exact selection the recall hook
  ships, run on every query. `kept` is the share of answerable queries whose first recalled
  entry is correct; `none_fp` is the share of no-answer queries for which recall returns
  anything. The gate is fixed in code, so the shipped default is measured, not assumed.

### Reading the results

- **hit@3 is at the ceiling for all three retrievers.** On this set, it cannot tell them
  apart. The likely reason is that one author wrote both the entries and the queries, so
  even the "paraphrases" share words with the bodies. This is the biggest limitation of the
  set, and the reason the CI gate is a regression floor, not a claim of quality.
- **Field weighting helps at rank 1, a little.** cairn misses rank 1 on 1 query, flat BM25
  on 2, substring on 4. Flat BM25 loses `find which commit broke the build` to the release
  skill; the title weight fixes it. Before the link fix the gap was larger (2 vs 5).
- **cairn still loses on false positives at the calibrated threshold.** With no threshold,
  every retriever returns something for 7 of 10 unanswerable queries. At the calibrated
  threshold cairn lets 2 through (`rust borrow checker: cannot borrow as mutable` reaches the
  mutable-defaults fact via `mutable` and `once`, `configure vim to indent with spaces`
  reaches the Makefile tabs issue via `indent` and `spaces`); substring lets 1 through.
- **The shipped recall gate is now the stricter operating point.** `cairn recall` returns
  nothing for 8 of 10 no-answer queries (the same 2 as above get through) and puts a correct
  entry first for 37 of 40 answerable ones. See the next section for what changed and what
  it cost.
- **Near-identical error messages stay hard.** `#!/bin/bash: No such file or directory`
  (a BOM problem) ranks the CRLF issue first for all three retrievers; the two entries share
  most of their vocabulary.

### Changes after the first run

The first published run found two gaps. Both were fixed without touching the queries, the
labels or the eval brain.

**1. `[[link]]` ids leaked into the index.** `rotate a leaked secret` ranked the `.gitignore`
issue first because its body says `follow [[rotate-a-leaked-secret]]`, and the id was
tokenized as body text. Search now indexes the body with link ids removed (`[[id|label]]`
keeps its label, since that is prose the author wrote into the sentence; code spans and
fences are untouched). The `links` graph, `outgoing_links()` and `cairn lint` are unchanged.
Link targets' titles are not indexed in their place: a `See [[x]]` line says where to read
next, not what the entry is about, and the target's title would carry the same words as its
id, so it would re-create the leak.

**2. Recall had no real no-answer gate.** The hook kept any hit scoring 1.5 or more, which let
5 of 10 no-answer queries through. Recall now also requires each hit to share at least two
distinct query words (`min_terms = 2`; all of them for a one-word query). The rule, and why it
is not a threshold fitted to these 50 queries:

- It has no fitted parameter. "At least two pieces of evidence" is the smallest rule that is
  stricter than "any one word", and it mirrors the BM25 fallback of the hot-issues board,
  which requires three shared words (see [hot-issues.md](hot-issues.md)). The
  score floor stays at 1.5, as shipped before this eval existed.
- It targets the failure mode the eval showed. BM25 gives a single rare word a high score on
  its own; that is how `terraform state lock could not be acquired` reached an npm
  lockfile issue through `lock`, and `java heap space` reached the Makefile tabs issue through
  `space`.
- An IDF-share rule (the share of the query's IDF mass the hit covers, as the hot-issues
  board uses for confidence) was considered first and rejected: correct top hits for
  paraphrases and for the agent task prompts cover as little as 15-25% of the query, which
  overlaps the no-answer queries (9-50%), so no share separates them.

The rule was designed after looking at per-query results, so it is not a blind test. Two
checks against overfitting: it is stable across an odd/even split of the queries, and the
neighbouring values show a smooth trade-off rather than a lucky point.

| `min_terms` | Correct first, answerable (40) | No-answer with any result (10) | Odd ids: kept / FP | Even ids: kept / FP |
| ---: | ---: | ---: | ---: | ---: |
| 1 (old behavior, after the link fix) | 39 (98%) | 5 (50%) | 95% / 40% | 100% / 60% |
| **2 (shipped)** | **37 (92%)** | **2 (20%)** | 95% / 20% | 90% / 20% |
| 3 | 33 (82%) | 0 (0%) | 85% / 0% | 80% / 0% |

`3` would remove every false positive here, but it drops 6 answerable queries, including
two-word vague prompts that are the normal shape of a recall query. `2` is the shipped
default; `--min-terms` on `cairn recall` changes it.

**Before and after.** "No-answer FP" is at each retriever's calibrated threshold; the last
row is the shipped recall hook.

| Retriever | hit@1 | hit@3 | MRR | No-answer FP |
| --- | ---: | ---: | ---: | ---: |
| cairn BM25F | 95% -> 98% | 100% -> 100% | 0.97 -> 0.99 | 20% -> 20% |
| BM25, no field weights | 88% -> 95% | 100% -> 100% | 0.94 -> 0.97 | 20% -> 20% |
| Substring match | 90% -> 90% | 100% -> 100% | 0.95 -> 0.95 | 10% -> 10% |
| cairn recall hook (correct first / FP) | 95% -> 92% | | | 50% -> 20% |

What improved: the link fix moves one query (`rotate a leaked secret`) to rank 1 for cairn,
and three for flat BM25, which shares the index code (among them `SQLite WAL mode
concurrency`, which the `database is locked` issue won through its link). The recall gate cuts the hook's
no-answer false positives from 5 of 10 to 2 of 10. What did not: hit@3 was already at the
ceiling; at the calibrated threshold cairn still has twice substring's false-positive rate
(the 2 survivors share two real words with an unrelated entry, which no lexical gate can
catch); and the gate costs 2 answerable queries (`big numeric ids get corrupted in the browser
frontend`, `money rounding`) where only one query word appears in the right entry, so recall
now stays silent on them. All 13 agent task prompts still recall a relevant entry in the top 3.

### Regression gate

`evals/retrieval/baseline.json` records cairn's hit@3. `python -m evals.retrieval` exits 1 if
the current value drops below it. CI also fails if `evals/results/retrieval.json` changes, and
a test compares a fresh run against the committed file, so the published numbers can't go
stale. After a deliberate change to search or to the eval brain, rerun, review the diff, and
commit the new results (and `--update-baseline` if the floor should move).

## Part B: agent A/B harness

### Tasks

13 small tasks, each a throwaway git repository built around one pitfall the brain documents.
`python -m evals.agent --list` prints them with their brain entries.

| Task | Pitfall the brain knows |
| --- | --- |
| `crlf-shebang` | CRLF shebang; the fix must also add `*.sh text eol=lf` or it comes back |
| `rg-glob-bat` | single-quoted `rg -g` glob in a `.bat` file matches nothing in `cmd.exe` |
| `npm-lockfile` | `npm ci` out of sync; switching CI to `npm install` is the known wrong fix |
| `json-bigint` | 64-bit ids lose precision in JavaScript; serialize as strings |
| `sqlite-locked` | `database is locked`; enable WAL, not just a longer timeout |
| `venv-windows` | `Scripts\python.exe`, not `bin/python.exe`, on Windows |
| `yaml-norway` | unquoted `NO` loads as `False` in YAML 1.1 |
| `docker-apt` | adding a package to a Dockerfile with a separate `RUN apt-get update` layer |
| `bash-pipefail` | `set -e` does not catch a failed `curl` in a pipeline |
| `utcnow-expiry` | `datetime.utcnow().timestamp()` is off by the local UTC offset |
| `git-untrack` | `.gitignore` alone does not untrack a committed file |
| `makefile-tabs` | `missing separator`: recipes need tabs |
| `sort-locale` | `sort` order depends on the locale; pin `LC_ALL=C` |

Prompts describe the symptom or the request, never the fix. Some tasks (`docker-apt`,
`crlf-shebang`) can be completed in a way that looks fine but keeps the known failure; those
are where recall should matter most.

### Checkers

Every task has a deterministic `check(repo)` that runs or inspects the result and reports:

- **passed**: the task is done and the fix is the durable one.
- **pitfall** ("repeated known failure"): the final state still shows the failure the brain
  warns about, for example a separate `RUN apt-get update`, or `config/local.env` still in
  the index.

Each task also carries a reference fix and a plausible naive fix. A test runs all three
states (untouched, naive, reference) through every checker and requires untouched and naive
to fail and the reference to pass, so a checker cannot silently accept everything.

### Arms and runners

For each task and repeat the harness runs two arms in fresh repositories:

- **`brain`**: the hits of `cairn.recall.recall` for the task prompt (the recall hook's
  selection: top 3, score floor 1.5, two shared words) are prepended to the prompt. Unlike
  the hook, which injects pointers (id, title, snippet, path), the harness inlines the full
  bodies, because the brain is not inside the throwaway repository. A retrieval miss is a
  miss here too.
- **`none`**: the bare prompt.

Runners:

- **`mock`** (CI): deterministic and free. It applies the reference fix when recall surfaced
  one of the task's brain entries and the naive fix otherwise. It tests the harness, the
  checkers and the recall step end to end. Its pass rates are true by construction and are
  **not evidence that the brain helps an agent**. The one real number it yields is recall
  coverage: on all 13 task prompts, a relevant entry is in the top 3.
- **`claude`**: Claude Code headless (`claude --print --output-format json`) in the task
  repository. `--bare` skips `CLAUDE.md` discovery, auto-memory, hooks and plugins, so neither
  arm sees the operator's own notes; web tools are disabled so the agent can't look the
  pitfall up; `--max-turns` and `--max-budget-usd` cap each run. It is skipped (exit 0) when
  the CLI or `ANTHROPIC_API_KEY` is missing.

Each run records pass/fail, repeated known failure, turns, input and output tokens, cost,
wall time, the recalled ids and whether recall hit a relevant entry. The report is a
brain-vs-none table plus a per-task matrix; the raw records go to
`evals/results/agent-<runner>.json`.

### Status

The harness is built and tested with the mock runner. **No real agent runs have been made
yet**, so there are no A/B results to report.

## How to run

```bash
pip install -e ".[dev]"

# Part A: prints the tables, writes evals/results/retrieval.json, gates on hit@3
python -m evals.retrieval
python -m evals.retrieval --update-baseline   # after a deliberate, reviewed change

# Part B: harness self-test, free
python -m evals.agent --runner mock
python -m evals.agent --list

# Part B: real runs with Claude Code (spends API credits)
export ANTHROPIC_API_KEY=...
evals/agent/run_claude.sh                                  # 13 tasks x 2 arms x 3 repeats
evals/agent/run_claude.sh --repeats 1 --tasks docker-apt --model sonnet
```

`run_claude.sh` writes `evals/results/agent-claude.json` and `agent-claude.md`. Commit both
with the model, the Claude Code version and the date in the PR description.

## Threats to validity

- **Small set.** 40 answerable and 10 no-answer queries; one query is 2.5 points of hit@k.
  Differences of one or two queries are noise.
- **Author-written queries.** The same person wrote the entries, the queries and the labels,
  which inflates lexical overlap and explains the hit@3 ceiling. A held-out set written by
  someone who has not read the brain is the most valuable next addition.
- **Lexical bias.** The queries were written by a person who knows the vocabulary. Real agent
  recall queries are task prompts and error output, which may share fewer words with the
  entries. The agent harness measures that path directly, but on only 13 prompts.
- **Synthetic brain.** 42 hand-written entries are cleaner and smaller than a brain grown by
  capture over months. Ranking gets harder as near-duplicates accumulate.
- **Threshold calibration.** The no-answer threshold is calibrated on the same answerable
  queries it is reported with. It is a fair cross-retriever comparison, not a tuned
  production setting. The recall gate is not calibrated, but it was chosen after seeing
  these queries (see "Changes after the first run").
- **Agent A/B.** Tasks are small, the pitfalls are well known, and a strong model may solve
  most of them without help, which would hide the brain's effect. Model output varies run to
  run, so use several repeats and report spread, not one run. Checkers can only see the final
  state, not whether the agent hit the error on the way.
